## 1. 已确认的背景与目的

用户对许多前端动画、布局等名词及规格不熟悉，遇到视觉效果或构思界面时，不知道如何准确表达，需要一个方便查阅和理解的项目。

项目要帮助用户表达脑中的想法，也帮助用户形成想法。后续希望可以接入 AI，实现自动化；自动化的具体对象和边界尚待讨论。

项目已作为 GitHub 公开仓库创建。首版首先服务作者自己，也向其他人公开查阅；首版无需登录，不提供跨设备同步，社区功能不属于当前已确认范围。

### 第一轮已确认结论

- 典型场景：设计 admin 后台布局，或为页面/组件设计过渡动画及其他动画时，知道想做什么，但不知道如何形容，也不知道相关术语。
- 受众：以作者自己的使用需求为优先，其他人可公开查阅。
- 内容范围：优先布局、动效、视觉风格、交互模式四类。通用编程概念不作为首版内容重点。
- 核心成果：理解术语和概念是基础，获得能向同事或 AI 准确传达意图的需求描述是核心。
- AI 节奏：用户接受先验证“找到效果 → 理解术语 → 输出描述”的建议；首版暂不接入在线 AI，后续再讨论自动化对象及接入方式。
- 已确认单词条描述与方案清单两种输出方式、少量可调预览参数、按作用对象组合需求、首版不提供完整实现代码复制和下载。
- Q16 最终确认：保留描述正文的手动编辑。手动编辑后再调整参数时提示“参数已变化，描述待更新”，由用户主动重新生成并确认替换；取消保留原文，首版不自动合并手写文本。

### 2.1 官方资料核对（Inspected，2026-10-26）

- Nuxt 官方注册表当前 `latest` 为 4.6.2，Node engines 为 `^22.22.3 || ^24.15.0 || >=26.0.0`。这是查询时的候选版本与运行要求，不代表本项目已经安装或通过验证。[包元数据](https://registry.npmjs.org/nuxt/latest)
- shadcn-vue 官方 Nuxt 集成支持 Tailwind、`@tailwindcss/vite` 与 `shadcn-nuxt`；组件源码进入项目，由项目维护。[Nuxt 安装](https://shadcn-vue.com/docs/installation/nuxt)、[组件说明](https://shadcn-vue.com/docs/introduction)
- Nuxt 静态生成产物没有运行时服务端 API。以后在项目内增加 AI API，需要服务端构建/托管环境，或者另接服务。[渲染模式](https://nuxt.com/docs/4.x/guide/concepts/rendering)
- Nuxt Content 支持 Markdown、frontmatter、内容集合与 Vue 组件；默认内部使用 SQLite，静态部署的客户端查询会使用 WASM SQLite。它免去自行运维内容数据库的工作，但仍有查询运行时成本。[Markdown](https://content.nuxt.com/docs/files/markdown)、[静态部署](https://content.nuxt.com/docs/deploy/static)
- Nuxt 官方有 Antfu 集成方案：Nuxt ESLint 模块关闭 standalone 默认配置后，与 Antfu 预设组合，保留 Nuxt 专属规则。[官方配置配方](https://eslint.nuxt.com/packages/module#custom-config-presets)
- pnpm catalog 管理依赖版本声明，不代替锁文件；Taze 官方说明支持 catalog 清单。[Catalogs](https://pnpm.io/catalogs)、[Taze](https://github.com/antfu-collective/taze)
- Pinia 提供 Nuxt 集成，VueUse 提供浏览器存储等组合式工具；选择它们后仍需明确客户端恢复、备份校验与版本迁移行为。[Pinia Nuxt](https://pinia.vuejs.org/ssr/nuxt.html)、[VueUse useStorage](https://vueuse.org/core/usestorage/)
- Vue 自带 Transition/TransitionGroup，支持与 CSS 动画配合；复杂演示是否需要额外动画库应由实际效果决定。[Vue Transition](https://vuejs.org/guide/built-ins/transition.html)

以上为访谈阶段的历史核对。2026-10-27 已实施首版，实际锁定版本、检查结果和兼容性约束见 [实现说明](implementation.md)。

Vercel 承载静态站点。实施时检查生成产物与站点配置，确保没有因采用默认服务端构建而引入运行时 Functions；当前只讨论部署设计，不视为已完成部署。具体构建配置在项目初始化后验证。[Vercel Nuxt 文档](https://vercel.com/docs/frameworks/full-stack/nuxt)

| Q15 | 组合方案是否需要整体运行预览？如何区分作用对象？ | 首版组合的是结构化需求描述，不拼装成完整可运行页面；每条选择标注作用对象，例如侧栏/页面内容/详情抽屉；同一对象冲突时提示并让用户选取，不静默覆盖 | 防止把“方案清单”误解为页面搭建器，避免混合无关对象的需求 |
| Q16 | 修改参数后如何保护手写描述？ | 保留描述编辑。手动编辑后参数变化时提示“参数已变化，描述待更新”；用户主动重新生成并确认替换，取消则保留原文；首版不自动合并手写文本 | 防止参数变化或重新生成覆盖用户已经写好的内容 |
| Q17 | 本地方案数量与备份迁移 | 可保存多个具名方案；支持复制/下载 Markdown 描述，以及 JSON 备份和导入，用于手动迁移收藏和结构化方案；不提供云端分享链接 | 区分给人或 AI 的文本交付与可恢复的本地数据 |
| Q18 | 页面与导航结构 | 首页直接是词条库（分类、搜索、效果卡片）；词条详情独立地址；收藏和我的方案可单独进入；方案编辑采用选择列表加描述区；桌面侧栏导航，移动收纳；原型覆盖空结果、空收藏/方案、预览异常、主题与移动布局 | 明确原型需要绘制的页面与状态，避免增加无关宣传页 |
| Q19 | 核心验收任务 | 以三个任务验收：找到“左侧导航可折叠、顶部固定、内容独立滚动”的布局并复制描述；找到“右侧进入的详情抽屉”并调整动效参数；把前两项加入具名方案，编辑描述、保存后刷新恢复并导出 | 将“能表达想法”变成可执行的验收用例 |

## 7. 首版产品方案与验收标准

### 7.1 核心使用流程

浏览分类或输入名称/通俗描述 → 找到效果 → 查看词条和操作预览 → 调整少量参数 → 复制单个词条描述，或加入方案并指定作用对象 → 编辑方案描述 → 本地保存、复制或导出。

首版优先服务作者在 admin 后台中的布局和动效表达，同时公开供其他人查阅。理解术语是基础，准确表达需求是核心成果。

### 7.2 内容与页面交付

- 内容：约 30–40 个高频词条，覆盖布局、动效、视觉风格、交互模式，优先后台场景；在仓库维护，由 AI 协助起草、作者审核。
- 词条：名称与别名、解释、示例、适用场景、相近概念差异、描述及参考来源；未统一的术语明确标注常见叫法或描述性命名。
- 页面：词条库首页、具有独立地址的词条详情、我的收藏、我的方案（列表与编辑视图）。
- 方案：可保存多个具名方案，按作用对象组合需求；相同对象的冲突选择须提示，不静默覆盖。
- 交付：词条预览独立运行，方案组合结构化描述；复制/下载 Markdown，导出/导入 JSON 备份以手动迁移收藏和方案。
- 设备：桌面优先，手机支持浏览、搜索和复制；桌面侧栏导航，移动收纳。
- 视觉：以 shadcn-vue 官方文档为主参考，加强内容层级、真实示例和信息密度；字体、配色及首屏细节按 Q33–Q35 执行：黑白灰为主、少量紫色强调、统一无衬线字体、详情大演示优先。支持三种主题，basic.pen 原文件保持不变。

### 7.3 描述编辑规则（Q14 与 Q16 的统一行为）

| 当前状态/操作 | 期望行为 |
| --- | --- |
| 尚未手动编辑描述，调整参数 | 预览与生成描述随参数更新 |
| 用户手动编辑描述 | 保留用户文本，允许复制、保存和导出 |
| 手动编辑后再改变参数 | 更新预览，保留描述原文，提示“参数已变化，描述待更新” |
| 用户主动重新生成 | 在替换手写文本前要求确认 |
| 用户取消替换 | 保留原文和待更新提示；不隐式撤销已调整的参数 |
| 用户确认替换 | 使用当前选择和参数生成的文本替换原文，解除待更新状态 |
| 本地保存后刷新 | 恢复词条选择、作用对象、参数、用户描述和对应的待更新状态，不用重新生成结果覆盖保存文本 |

不做手写文本的自动合并。参数调整能力与描述编辑能力分别保留。

### 7.4 原型检查清单

- 词条库：首页分类、检索、效果卡片及无结果状态。
- 词条详情：名称与解释、预览、参数调整、默认值恢复、相关概念、复制及加入方案入口。
- 收藏与方案：空状态、已有内容状态、具名方案的列表和编辑视图。
- 方案编辑：词条选择与作用对象、冲突提示、描述正文、参数变化后的待更新提示、重新生成确认与取消路径、保存与导出入口。
- 基础状态：预览异常、明暗主题、移动端导航与主要页面布局。
- PWA：桌面安装入口、手机安装指引、离线资源准备中/已就绪/失败、新版本提示、保存后更新和保存失败保留输入。
- Pen 用于展示页面、状态和交互说明；实际动画、检索与本地恢复等运行行为在代码实现后验证，不能以静态原型代替运行验收。

### 7.5 验收任务

| 编号 | 操作场景 | 通过条件 |
| --- | --- | --- |
| AC1 | 不知道术语，寻找“左侧导航可折叠、顶部固定、内容区域独立滚动”的布局 | 可通过分类、效果卡片或已维护的通俗描述找到对应内容，看懂名称和示例，并复制准确描述 |
| AC2 | 寻找“详情抽屉从右侧进入”，调整动画参数并重播 | 可观察到对应变化，未手写的生成描述体现当前参数；可恢复默认 |
| AC3 | 将布局和抽屉加入“订单管理后台”方案 | 可分别指定作用对象，形成结构化描述；同一对象发生选择冲突时提示并由用户处理 |
| AC4 | 手写方案描述，再改变参数 | 原文不被覆盖，显示待更新提示；重新生成须确认；取消保留原文，确认后才替换 |
| AC5 | 保存方案后刷新，再复制或导出 | 恢复保存的选择、参数、手写文本及待更新状态；可复制/下载 Markdown；JSON 备份可导入恢复收藏与方案 |
| AC6 | 使用手机及不同主题浏览 | 浏览、搜索与复制可用；浅色/深色/跟随系统正常；预览遵循减少动态效果设置，列表不会同时播放全部动画 |
| AC7 | 首次联网访问并完成离线缓存后，断网重开应用 | 未逐一访问过的首批词条、本地演示、搜索、收藏和方案编辑仍可用；外部参考链接标明需联网 |
| AC8 | 首次缓存尚未完成、缓存失败或被清理 | 不显示“已可离线使用”；明确准备中或失败状态，并提供恢复入口 |
| AC9 | 编辑方案时出现新版本，选择稍后或保存后更新 | 稍后不刷新；保存成功再更新；保存失败保留页面与输入；更新后收藏、方案、手写文本和待更新状态仍存在 |
| AC10 | 在支持 PWA 安装的桌面/手机浏览器中安装 | 按能力显示安装按钮或对应指引；不支持安装的浏览器仍可正常使用网页 |

### 7.6 首版边界

- 首版无后端，后续静态部署到 Vercel；PWA 按 Q27–Q29 的完整首批离线、保存后更新与平台安装方案执行。
- 不接入在线 AI，不承诺任意自然语言的语义理解；检索使用名称、别名和已维护的通俗描述。
- 不做登录、云端同步或云端方案分享；本地数据可能因浏览器清理而丢失，提供备份导入导出。
- 不做网页内容管理后台，词条在仓库中维护。
- 不做拖拽搭建器或组合方案的完整页面运行预览。
- 不提供完整实现代码的复制/下载，不自动合并手写描述。
